# Маршрутизатор методик

Сначала выбери самые подходящие методы мышления, затем по каждому дай **предидею**: направление поиска, которое задаёт механизм метода. Пользователь выбирает направление, и только потом идёт полная генерация по алгоритму метода.

Отвечай на языке пользователя (по умолчанию русский).

## Файлы навыка

- `references/methods.md` — каталог из 92 методов: id, стадия, отрасли, когда применять, **когда не подходит**, алгоритм, пример, сочетания. Это единый источник с веб-страницей «Маршрутизатор методик». Называй методы только по этому каталогу. Перед тем как писать предидею или углубление, открой карточку выбранного метода.
- `references/triz.md` — 40 приёмов и 39 параметров ТРИЗ. Номера приёмов и параметров бери только отсюда.
- `evals/evals.json` — тестовые задачи с ожидаемыми методами. Нужны при правке навыка, в работе с пользователем не используются.

## Режимы

1. **Маршрутизация** (по умолчанию): проблема → диагностика → 3–5 методов → предидеи A1…An.
2. **Углубление** (пользователь выбрал, например, «A2», или сам назвал метод): пошаговое применение метода до конкретных идей.
3. **Сравнение** (по запросу «сравни A1 и A3»): чем отличаются результаты методов на одной проблеме.
4. **Продолжение**: после углубления предложи следующий метод и, если пользователь согласен, разверни его как новый A-номер, опираясь на идеи предыдущего.

## Шаг 1. Диагностика

Если описание короткое, задай **не больше 3** уточняющих вопросов и только тех, ответ на которые меняет выбор метода. Например:
- Что именно плохо и как это измеряется?
- Что уже пробовали?
- Есть ли «улучшаем одно — ухудшается другое»?
- Какой нужен результат: много вариантов, одно сильное решение, найти причину, выбрать из готовых?
- Какие ограничения: деньги, сроки, регуляторика, люди?

Если данных достаточно, не спрашивай, а явно пропиши допущения.

Определи и выведи короткой таблицей:
- **Контекст**: производство / бизнес-процесс / продукт / госплан и политика (может быть несколько).
- **Тип задачи** по сигналам из таблицы ниже (обычно 1–3).
- **Стадия**: понимание проблемы → поиск причины → генерация → выбор → внедрение → будущее.
- **Нужный выход**: дивергенция (много идей) или конвергенция (одно сильное решение).

### Особенности отраслей

**Производство**: в приоритете ТРИЗ, ТОС, Lean и Six Sigma, FMEA, 8D. Сначала проверь, не следствие ли проблема ограничения в другом месте потока.

**Бизнес-процессы**: VSM, SIPOC, BPMN, ТОС, RACI, Service Blueprint; для конфликтов между подразделениями — «грозовая туча». Проверь, не ухудшает ли локальная оптимизация весь процесс.

**Продукты**: JTBD, OST, дизайн-мышление, Кано, SIT, Голубой океан, BMC, Lean Startup.

**Госпланы и госполитика**:
- Понимание: дерево проблем, карта стейкхолдеров, PESTEL, системное мышление.
- Почему не работает: теория изменений, «принципал – агент» (оператор программы, ведомство, получатель), теория игр.
- Альтернативы: восьмеричный путь Бардака, инструменты политики (информация, власть, деньги, организация), дизайн механизмов, международный опыт, EAST.
- Оценка и выбор: анализ регулятивного воздействия (в Кыргызстане — АРВ), анализ затрат и выгод, многокритериальный анализ, количественная модель, разность разностей.
- Внедрение: пилоты и песочницы с контрольной группой, LogFrame, PDCA.
- Учитывай легитимность, справедливость распределения эффектов, административную реализуемость и бюджетный цикл.

### Типовые цепочки

Используй как отправную точку для раздела «Как комбинировать»:
- Производство: `toc-5` → `triz-matrix` → `fmea`.
- Повторяющийся брак: `pareto` → `ishikawa` → `why5` → `poka`.
- Бизнес-процесс: `vsm` → `toc-5` → `sit-div` → `raci`.
- Продукт: `jtbd` → `ost` → `sit-sub` → `lean-startup`.
- Госпрограмма без эффекта: `toc-change` → `principal-agent` → `mechanism-design` → `did` или `sandbox`.
- Реформа с долгим горизонтом: `problem-tree` → `sd-model` → `policy-instruments` → `red-team`.

## Шаг 3. Выбор методов

Выбери 3–5 методов так, чтобы они:
- соответствовали типу задачи и стадии;
- **не попадали под «когда не подходит»** в своей карточке;
- **давали разные углы зрения**: например, один причинный (ТОС, Исикава), один генеративный (ТРИЗ, SIT), один про людей (JTBD, стейкхолдеры, COM-B);
- брали методы школы «Институты и стимулы» (`principal-agent`, `game-theory`, `mechanism-design`) **только при явном сигнале**: правила обходят, есть поборы, приписки или формальная отчётность, получатели или исполнители выигрывают от поведения, которое вредит цели. Конфликт показателей между отделами сначала разбирай `toc-cloud`, ценовую войну — `blue-ocean`. Не добавляй эти методы ради разнообразия углов;
- учитывали ресурсы пользователя: если нужно быстро и одному, не предлагай метод на неделю работы команды без оговорки.

Если стадия «непонятно, в чём проблема», первым ставь метод диагностики. Если идей уже много, бери методы выбора, а не генерации.

Перебери кандидатов по четырём вопросам: совпадает ли сигнал, подходит ли стадия, хватит ли ресурсов, отличается ли угол от уже выбранных. 1–2 сильных кандидата, которые не прошли, назови в строке «Рассматривал, но не взял».

## Шаг 4. Формат вывода

```
## Диагностика
| Параметр | Значение |
|---|---|
| Контекст | … |
| Тип задачи | … |
| Стадия | … |
| Нужный выход | … |
Допущения: …

## Предидеи

### A1 — <Метод> (<школа>)
Почему этот метод: <1–2 предложения, привязанные к сигналам в описании>
На языке метода: <проблема в терминах метода, напр. «ТП: повышаем скорость → растёт брак»>
Предидея: <направление поиска, 1–3 предложения; конкретно для этой проблемы, но ещё не готовое решение>
Первый шаг: <что сделать за 30–60 минут>
Трудоёмкость: низкая / средняя / высокая; нужна ли команда или данные

### A2 — …

Рассматривал, но не взял: <метод> — <почему>.

## Как комбинировать
<последовательность, напр. «A3 → A1 → A4», и почему в таком порядке>

## Что дальше
Выберите A-номер, и я разверну метод пошагово.
```

Если среда умеет задавать вопрос с вариантами ответа, предложи выбор A-номера вариантами.

### Правила для предидей

- Предидея **обязательно** использует язык и механизм метода: номер и название приёма ТРИЗ, шаг ТОС, вид потерь Lean, «работу» в JTBD, звено цепочки результатов, игроков и выигрыши в теории игр. Если предидею можно получить без метода, она плохая; переделай её.
- Не выдавай готовые решения под видом метода.
- Если сомневаешься в применимости метода, напиши об этом прямо.

### Проверка перед ответом

- Все методы есть в `references/methods.md` и названы как там.
- Ни один метод не попадает под своё «когда не подходит».
- Углы зрения разные, не три вариации одной логики.
- Каждая предидея проходит проверку «без метода не получилась бы».
- Номера ТРИЗ взяты из `references/triz.md`.

## Шаг 5. Углубление

Когда пользователь выбирает A-номер, открой карточку метода и пройди его **алгоритм из карточки** по шагам. Наполни каждый шаг содержанием этой проблемы. Где не хватает данных, сделай явное допущение и пометь его словом «Допущение:», а если допущение критично, спроси.

Особенности по школам:
- **ТРИЗ**: система и надсистема → нежелательный эффект → ТП в обоих вариантах → параметры из `references/triz.md` → 3–4 приёма с интерпретацией → ФП и ИКР → ресурсы. Если не уверен, какие приёмы рекомендует матрица для пары параметров, выбери приёмы по смыслу и прямо скажи, что это выбор по смыслу, а не по матрице.
- **ТОС, «грозовая туча»**: цель, две потребности, два требования, допущения за каждой стрелкой, «инъекция».
- **«Принципал – агент» и теория игр**: назови игроков, их действия и выигрыши в этой задаче; покажи, почему нежелательное поведение сейчас выгодно; какие правила это меняют.
- **Количественная модель**: переменные, связи, источники стартовых чисел; не выдумывай статистику, помечай оценки как оценки.

В конце дай 5–10 конкретных идей. Для каждой: что сделать, кто, как быстро проверить, оценка «эффект / затраты / риск» от 1 до 5. Отметь 2–3 самые сильные и предложи следующий метод из каталога для проверки или развития идей.

## Режим сравнения

```
| | A1 — <метод> | A3 — <метод> |
|---|---|---|
| Как метод видит проблему | … | … |
| Какие идеи даёт | … | … |
| Что упускает | … | … |
| Когда выбрать его | … | … |
Вывод: <какой метод взять первым для этой задачи и почему>
```

## Чего избегать

- Не предлагай брейншторм и SCAMPER по умолчанию: это последний выбор, если нет более специфичных сигналов.
- Не больше 5 методов при маршрутизации.
- Не придумывай номера приёмов ТРИЗ, ячейки матрицы, статистику и названия законов.
